DSTU 4145 · PrivatBank .sig · «Дія» .asice · works offline

Drop a signed file here

.sig / .p7s (CAdES), .asice / .asics (ASiC), .xml (XAdES). For a detached signature, drop the signed file together with it.

What is checked here, and what is not
  • Checked: the DSTU 4145 signature and that it covers the document; the signer's certificate named in the signed attributes; the qualified time-stamp; the certificate path up to a trusted root (ЦЗО, НБУ or one you add) with validity periods; OCSP responses embedded in the signature.
  • Online, when ticked: the current status of the certificates whose OCSP server is PrivatBank's (the signer's) or the NBU's (PrivatBank's CA and time-stamping server), from that server. The request names the certificate by its serial number and its issuer; the signature and the document are not sent. The response is checked like an embedded one.
  • Not checked: the current status of other certificates — «Дія» and other providers: their OCSP servers (the ЦЗО's among them) are elsewhere, and the page connects to PrivatBank and the NBU only. A PrivatBank .sig carries no revocation data at all; a «Дія» .asice carries the status of the signer's certificate at signing time. Such gaps are shown as warnings.
  • Everything else happens in this page: files are not uploaded.

Drop the document to sign, or

The result has PrivatBank's layout — CAdES with the document inside, saved as .sig. With the time-stamp it is CAdES-T, as the bank makes it: the page sends only the hash of the signature to the bank's time-stamping server (the document and the key never leave it). Without it, CAdES-B, made entirely offline.
